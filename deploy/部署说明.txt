------------------------------------------------------------
  0. 自检：管理员权限 / 包完整性 / 产物是否真的带 /workspace/ 前缀
  1. URL Rewrite 2.0 未安装则从微软官方 CDN 静默安装（已装则跳过）

------------------------------------------------------------
五、注意事项 / 已知限制
------------------------------------------------------------
  * Supabase（可选）：要在线上用注册登录/邮件重置，需去 Supabase 控制台
    Auth → URL Configuration，把 Site URL 与 Redirect URLs 加上
    http://124.220.159.58/workspace/
    否则邮件里的验证/重置链接会跳回原来的地址。
  * 纯 HTTP + IP 属于浏览器定义的「非安全上下文」，两类 API 会被禁用：
      - Geolocation（天气自动定位）→ 自动走降级链：上次城市 / 默认城市，功能不挂
      - Notification（网页版系统通知）→ 应用内铃铛/Toast 兜底正常；
        桌面版 exe 走 Windows 原生通知，不受影响
    升级路径：绑域名 → 解析到本 IP → IIS 绑域名 + win-acme 免费证书 → HTTPS 全解锁。
  * 子路径部署必须用 BASE_PATH=/workspace/ 构建（本包已经构建好）。
    用默认 base 的产物会白屏——install.ps1 里已加这条自检。

------------------------------------------------------------
六、常见故障排查
------------------------------------------------------------
  「没有找到绑定 80 端口的站点」（老版本脚本的已知问题，本包已修复）：
      原因：Get-Website 返回的 Bindings 是 IIS 配置对象，直接匹配只能拿到类型名
      （Microsoft.IIs.PowerShell.Framework.ConfigurationElement），所以探测不到绑定。
      本包已改为经 .Collection 读 bindingInformation，并加了 Get-WebBinding 与
      「只有一个已启动站点就直接用」两层兜底。
      万一仍然遇到（比如解压的是旧包）：给脚本显式指定主站名即可，例如
          powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -SiteName "Default Web Site"

  白屏 / 控制台一堆 404：
      产物 base 不对。用 BASE_PATH=/workspace/ 重新构建再打包
      （scripts/build-deploy-package.ps1 已自动带上）。

  HTTP 500.19（配置错误，提示 rewrite 节无法识别）：
      URL Rewrite 模块没装上。重跑 install.ps1，或手动装 msi 后执行 iisreset。

  HTTP 404.3（静态文件被拒）：
      MIME 类型缺登记。本包 web.config 已补 .js/.json/.webp/.woff2 等；
      确认 web.config 确实被复制到了目标目录。

  刷新子路由 404：
      web.config 的 rewrite 规则没生效（多半还是 URL Rewrite 未安装）。

  主站受影响：
      本包只写 <主站根目录>\workspace\ 一个目录，web.config 写在子目录里，
      IIS 配置继承方向是从父到子，主站根目录不受任何影响。
      真要回退：IIS 管理器里删掉 workspace 子应用即可（或删除该目录），
      主站配置无需还原。
